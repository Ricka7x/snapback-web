# Release Process Report

## Overview

Two repos are involved in every release:

| Repo | Path | Purpose |
|------|------|---------|
| App repo | `~/Projects/Snapback` | Source code, Xcode project |
| Web repo | `~/Projects/snapback-web` | Release pipeline, website, GH Pages host |

The release scripts live in a third, shared repo:

| Repo | Path | Purpose |
|------|------|---------|
| `macos-release-tools` | `~/Projects/macos-release-tools` | Generic macOS release automation (submodule at `snapback-web/scripts/`) |

---

## Before (what the process looked like)

### Problems

| # | Problem | Impact |
|---|---------|--------|
| 1 | App repo had no git tags | No way to correlate commits to a release |
| 2 | Release notes were never generated | Users saw a blank update dialog in Sparkle |
| 3 | Version bump was owned by the release script via `agvtool` | Version history was disconnected from code history |
| 4 | `config.sh` was inside the scripts repo | Tools could not be reused on other projects |
| 5 | Release notes required manual writing | Easy to skip, inconsistent |
| 6 | No changelog | No record of what changed per version |

### What an appcast entry looked like

```xml
<item>
    <title>0.3.5</title>
    <sparkle:version>23</sparkle:version>
    <sparkle:shortVersionString>0.3.5</sparkle:shortVersionString>
    <enclosure url="..." ... />
    <!-- No <sparkle:releaseNotesLink> — update dialog was blank -->
</item>
```

---

## After (how it works now)

### Principles

- The **app repo is the source of truth** for what changed
- The **release script is a deploy pipeline** — it consumes from the app repo, not invents context
- **Version is determined automatically** from commit history via `git-cliff` (feat → minor, fix → patch)
- **Release notes are generated automatically** from conventional commit messages
- Every release is **tagged in the app repo** so history is always recoverable
- The **scripts are project-agnostic** — any macOS app can use them with its own `config.sh`

### How it works now

```
[App Repo]                              [Web Repo / Release Repo]
    |                                            |
    | 1. Developer commits freely               |
    |    fix: ..., feat: ...                    |
    |    (no version touching)                  |
    |                                            |
    |                        2. cd ~/Projects/snapback-web
    |                           ./scripts/build-and-release.sh
    |                                            |
    |                        3. git-cliff reads commits since
    |                           last tag (v0.3.5)
    |                           feat: found → minor bump → v0.4.0
    |                           fix: only  → patch bump → v0.3.6
    |                                            |
    | 4. Info.plist + pbxproj ◄──────────────────┤
    |    written with new version                |
    |                                            |
    |                        5. xcodebuild archive
    |                           notarize + staple
    |                           create DMG       |
    |                                            |
    |                        6. git-cliff generates
    |                           releases/Snapback-X.Y.Z.html
    |                           from feat:/fix: commits
    |                                            |
    |                        7. generate-appcast.sh regenerates
    |                           appcast.xml with
    |                           <sparkle:releaseNotesLink>
    |                                            |
    | 8. Version bump committed ◄────────────────┤
    |    to app repo                             |
    |                                            |
    | 9. App repo tagged ◄───────────────────────┤
    |    v{VERSION}, pushed                      |
    |                                            |
    |                       10. Web repo committed + pushed
    |                           DMG + appcast + HTML notes
    |                           GH Pages deploys automatically
```

### What an appcast entry looks like now

```xml
<item>
    <title>0.3.6</title>
    <sparkle:version>24</sparkle:version>
    <sparkle:shortVersionString>0.3.6</sparkle:shortVersionString>
    <sparkle:minimumSystemVersion>12.4</sparkle:minimumSystemVersion>
    <sparkle:releaseNotesLink>https://snapbackapp.com/releases/Snapback-0.3.6.html</sparkle:releaseNotesLink>
    <enclosure url="..." ... />
</item>
```

### What a generated release notes file looks like

```html
<!-- releases/Snapback-0.3.6.html — auto-generated by git-cliff -->
<h3>What's new in 0.3.6</h3>
<h4>New Features</h4>
<ul>
  <li>add command palette shortcut customization</li>
</ul>
<h4>Bug Fixes</h4>
<ul>
  <li>spacing between import and export buttons</li>
  <li>frame constraints in Command Palette layout</li>
</ul>
```

## Repo structure

```

├── scripts/                ← git submodule → macos-release-tools

│   ├── release.sh
│   ├── generate-appcast.sh
│   ├── cliff.toml
│   ├── config.example.sh

│   ├── dmg-settings.py
│   └── assets/
├── releases/
│   ├── Snapback-X.Y.Z.dmg
│   ├── Snapback-X.Y.Z.html  ← auto-generated release notes
│   └── appcast.xml

```
